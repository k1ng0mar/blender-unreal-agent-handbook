This presentation, titled **"Getting Started with Scripting in Python,"** was delivered by Mike Shah at the Blender Conference 2023 (BCON23). It provides an introductory tutorial on leveraging Python to automate tasks and extend functionality within Blender 3D.

### **Summary of the Talk**
The session introduces the Blender Python API (`bpy`) by walking through the creation of a custom "Bounding Box" tool. Shah demonstrates how to transition from manual UI interactions to interactive console commands, and finally to a reusable add-on. The talk emphasizes a "learning by doing" approach, showing users how to "reverse engineer" Blender’s internal operations to write their own scripts.

### **Practical Guidance on Blender Python Scripting**

#### **1. The Scripting Workspace**
Blender includes a dedicated **Scripting Workspace** consisting of four essential windows:
*   **3D Viewport:** To visualize changes in real-time.
*   **Python Console:** Ideal for quick testing, querying information, and getting immediate feedback.
*   **Info Log:** A critical tool that displays the Python equivalent of almost every action performed in the UI (e.g., moving a cube or extruding a face).
*   **Text Editor:** Used for writing, saving, and executing multi-line scripts and add-ons.

#### **2. API Exploration Tools**
*   **Python Tooltips:** Enabled via *Edit > Preferences > Interface*. Hovering over any UI element reveals its specific Python API path.
*   **Auto-completion:** Pressing `Tab` in the Python Console provides a list of available attributes and methods for a given module or object.
*   **Built-in Help:** Using `help(bpy.data)` or `type(myObject)` in the console provides documentation and class information directly within Blender.

---

### **Automation Workflow**

1.  **Manual Discovery:** Perform the desired action in the UI and observe the **Info Log** to see the generated `bpy.ops` command.
2.  **Console Testing:** Copy the command into the **Python Console** to verify it works programmatically.
3.  **Script Development:** Move the logic into the **Text Editor**. Use `bpy.context.active_object` to target the user's current selection.
4.  **Add-on Conversion:** Wrap the script in a class inheriting from `bpy.types.Operator` and define a `bl_info` dictionary to make it a formal Blender add-on.

---

### **API Usage and Core Modules**

*   **`bpy.context`:** Captures the current state of the user interface, such as the active object or selected vertices.
*   **`bpy.data`:** Provides access to Blender's internal data-blocks (meshes, materials, textures, etc.). For example, `bpy.data.meshes` contains all geometric data.
*   **`bpy.ops`:** Contains "operators" or functions that perform actions (e.g., `bpy.ops.mesh.primitive_cube_add`).
*   **`bmesh`:** A more advanced module for complex mesh editing that allows for direct manipulation of vertices, edges, and faces.

---

### **Common Pitfalls**

*   **Brittle Scripts:** Scripts that assume an object is always selected may crash if run on an empty scene. Shah recommends using `try/except` blocks to handle errors.
*   **Context Sensitivity:** Some operators only work in specific modes (e.g., Edit Mode vs. Object Mode). Scripts must ensure the correct mode is active before execution.
*   **Performance:** Iterating through thousands of vertices in a standard Python loop can be slow; for heavy computations, specialized API methods or `numpy` are preferred.

---

### **Agent-Relevant Lessons**

*   **UI as a Teacher:** The most effective way to learn the API is to watch the **Info Log** while interacting with the software. This allows an agent (or human) to map visual actions to code.
*   **Parenting for Transformation:** When creating helper geometry (like a bounding box), setting the original object as the `parent` ensures the helper automatically follows any subsequent moves, scales, or rotations.
*   **Handlers for Real-time Updates:** Use `bpy.app.handlers` to trigger scripts automatically when a scene changes (e.g., recomputing a bounding box every time a vertex is moved).
