This presentation by Marcus White, Principal Technical Artist at Unit 2 Games, details how a small team (approx. 30 people) uses Python to automate asset workflows in Unreal Engine 4 (UE4) for their game, *Crayta*.

### **Practical Guidance on Unreal Editor Python Workflows**

#### **1. Implementation Options**
White identifies two primary ways to use Python in Unreal:
*   **Official Unreal Python (Epic):** Released in UE 4.19. It uses Python 2.7 and is primarily for editor scripting.
*   **UnrealEnginePython (3rd Party):** A GitHub-based plugin that Unit 2 Games utilized because they started on UE 4.18. It supports Python 2.7, 3.5, and 3.6, providing deeper access to the UE4 reflection system and internal APIs.

#### **2. Automation Architecture: Asset Ingestion**
The team automated the ingestion of outsourced props to reduce human error and iteration time.
*   **Preparation:** Outsourcers assign materials in Maya that match the names in the team’s internal material library.
*   **Texture Baking:** The pipeline uses `sbsbaker.exe` (part of the Substance Automation Toolkit) to generate Curvature and Ambient Occlusion maps automatically.
*   **Image Processing:** The **Python Image Library (PIL)** is used to:
    *   Convert Maya texture associations into a single-channel ID map.
    *   Pack different components (Curvature, AO, ID) into the Red, Green, and Blue channels of a final "Control" texture.
*   **Unreal Integration:** A custom Slate UI window in the editor allows artists to select a directory and batch-import assets with a single click, automatically setting up materials via the Substance plugin.

#### **3. Automation Architecture: Asset Management**
To track the production state of hundreds of assets, the team integrated Unreal with **Trello**.
*   **API Wrapper:** They used the `py-trello` library to communicate with Trello’s web API.
*   **Metadata Sync:** The script uploads asset thumbnails, metadata, and **Perforce history** (tracking who modified an asset and when) to Trello cards.
*   **Status Tracking:** The system automatically calculates and updates an asset's production state (e.g., whitebox vs. final) based on the metadata found in the engine.

---

### **Validation and Common Failure Modes**

*   **Human Error in Manual Setup:** Manual ingestion was identified as the primary failure point, leading to inconsistent material assignments and broken naming conventions.
*   **Art Style Inconsistency:** By forcing a Substance-based workflow through automation, the team ensures that both internal artists and outsourcers maintain a consistent style, which is critical for their user-generated content (UGC) goals.
*   **Data Format Changes:** White notes that Python is ideal for "incidentals"—batch-fixing assets when data formats or engine requirements change mid-project.

---

### **Game Development Agent Lessons**

*   **Iteration Speed:** Python’s lack of compile times allows for "trial and error" development of editor tools, which is significantly faster than C++ for UI and pipeline logic.
*   **Distribution:** Python scripts are easy to distribute across a team via source control (Perforce) without requiring new engine builds.
*   **Efficiency Threshold:** The talk includes a "Scripted vs. Manual" graph, demonstrating that while scripting has a higher initial time cost, it remains efficient as the "size of task" increases, whereas manual labor scales linearly and becomes unsustainable.
*   **Empowerment:** Python allows Technical Artists to solve pipeline problems without taxing the limited bandwidth of the core engineering team.
